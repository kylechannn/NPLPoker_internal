# Wheel verification

TDs and ordinary Admins scan the player on the OS and select **Send photo request to phone**. The OS uses its actual active session and licensed device identity. Staff bind their iOS/Android phone with that session's existing Admin QR, open **Wheel photo requests**, and photograph/select a clear hand photo there. The desk waits for a Super Admin to review the phone's photo on the website or phone. Approval marks the phone task finished and opens the existing OS wheel; the operator presses **SPIN**. Super Admin operators can spin directly.

The request expires 15 minutes after the OS creates its draft, including time spent taking the photo and waiting for review. Photo submission and review never extend it. One approval authorizes one spin for that player, operator, licensed device, linked game session, venue and wheel tier. Rejection/expiry requires a new phone photo and request. A golden follow-up requires a separate approval referencing the original normal spin. Existing eligibility rules and prize issuance are unchanged.

The console retains the operator's admin token for this verification. A stale sign-in prompts for the same operator's password; waiting requests survive reauthentication. Cloud failures stop wheel entry and preserve the reference for a safe retry. The request is consumed only after the backend records the award. A retry of a completed draw retrieves that award rather than issuing another prize.

The OS sends JSON only; it has no camera/upload controls. Only a phone currently bound to the request's exact session may submit a photo. The backend stores photos privately and signs temporary review URLs. Super Admin approval emits `wheel.approval.updated` on the existing desk realtime connection with the request ID only; the OS reads the authenticated state immediately, with a five-second polling fallback. Photo tasks can also be opened directly in the phone app if a popup is missed.

Deploy the backend migrations `2026_09_30_220000_create_wheel_spin_approvals` and `2026_10_01_000200_add_bound_phone_wheel_requests`, updated OS and both native apps together. Old OS hand-photo submissions are refused. This wheel change needs no new local table; the cash-table controls in the same release do add a local mirror migration. Backend deployment notes live in `docs/database/MIGRATION_PLAN.md` and `docs/WHEEL_PHONE_VERIFICATION.md` in NPLPoker_backend.

Local validation includes the OS proxy tests and browser checks of phone-only handoff, lost-response retry after refresh, realtime state changes, the linked game session in the draw, and recovery after the player's last entitlement was used. Physical iOS/Android camera and production push delivery still need the normal device release check.
