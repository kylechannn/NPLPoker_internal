# Wheel verification

TDs and ordinary Admins scan the player on the OS and select **Send photo request to phone**. The OS uses its actual active session and licensed device identity. Staff bind their iOS/Android phone with that session's existing Admin QR, open **Wheel photo requests**, and photograph/select a clear hand photo there. The desk waits for a Super Admin to review the phone's photo on the website or phone. Approval marks the phone task finished and opens the existing OS wheel; the operator presses **SPIN**. Super Admin operators can spin directly.

The request expires **60 minutes after the OS creates its draft**, including photo and review time. Uploading and review never extend it. One approval authorizes one normal spin for that player, operator, licensed device, linked game session and venue. Rejection/expiry requires a new phone photo and request. An earned golden follow-up opens automatically without a second photo/approval; the backend verifies the original normal draw, operator, desk and player, and only one golden award is allowed. Every active staff member receives a persistent Golden Wheel notice in Staff Inbox.

Eligibility follows Jackpot Control's existing setting. `operator` requires an active player; staff judge the qualifying hand. `jackpot_entry` additionally requires an unused entry for today's Australia/Sydney date, consumed by the normal draw. A golden follow-up consumes no additional jackpot entry. Photo approval does not create an entry.

While the wheel is open the OS renews the operator's login within five minutes of expiry through `POST /api/v1/console/refresh`, preserving the identity and original approval deadline. A failed/expired sign-in prompts for the same operator's password; waiting requests survive reauthentication. Cloud failures preserve the reference for safe retry. Approval is consumed only after the backend records the award. Retrying a completed draw retrieves that award without issuing another prize.

The OS sends JSON only; it has no camera/upload controls. Only a phone currently bound to the request's exact session may submit a photo. Photos are private with signed temporary review URLs. Approval emits `wheel.approval.updated` on the existing desk realtime connection with the request ID only; the OS reads authenticated state immediately, with a five-second polling fallback. Returning online, focusing the window or making the page visible also triggers a check. Requests bypass browser cache and time out after 30 seconds so a dead connection cannot block polling forever. Tasks remain accessible directly in the phone app if a popup is missed.
